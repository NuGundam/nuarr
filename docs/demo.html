THE JOB GATE

Viewers always win

The moment somebody presses play, the gate reacts — new jobs prefer the other spindles, anything already running on the viewer's disk drops to Very Low I/O so their reads overtake it, and if their buffer runs genuinely thin, work on that spindle stops outright until it recovers. When the session ends, a grace period keeps things calm, then the queue resumes on its own. Nobody has to remember to pause anything.

VIEWER-AWARE PACING

It knows exactly how close you are to a stutter live logic

nuarr measures every viewer's real buffer — from the server's own file position — and paces itself against it on a sliding scale: full speed when you're far ahead, progressively slower as your runway shrinks, and a hard stop (the encode is frozen mid-frame, not killed) if you dip under the floor. Stopping and starting use different thresholds, because pausing is itself what lets the buffer recover — one threshold flapped every few seconds; two never do.

220s of runwaynuarr at full speed
0s50s75s 150s180s+
50s — nuarr stops 75s — nuarr starts again (after holding) 150s — nuarr at full speed

And the floor isn't one number — it's computed per stream. Seconds aren't disk work: 60s of a 25 Mbps 4K remux is 189 MB off the spindle, 60s of a 6 Mbps episode is 44 MB. So the floor scales with bitrate — then gets capped by two things the system can't exceed: what this player has actually been measured holding (client buffers are capped in megabytes, so a 4K stream holds fewer seconds), and where Plex parks its own encoder (TranscoderThrottleBuffer, read live from the server). Demanding more than either would leave a healthy stream reading as "starving" forever.

AUDIO THAT ACTUALLY PLAYS

The end of the buffering wheel

Plex's audio decoder silently rejects high-bitrate E-AC3 — the stream buffers forever and nobody knows why. Nuarr found the pattern, proved it on real sessions, and made the fix a standing rule: every incompatible track is re-encoded to the rate Plex direct-plays, automatically, forever. It also downmixes 7.1 where needed, keeps lossless above lossy when deduplicating, and keeps both languages on dual-audio anime.

WHEN METADATA LIES

It listens to the file

A blank language tag isn't neutral — Sonarr, Radarr and every player read it as English, so a mistagged Japanese track plays the wrong audio. Filename inference can't catch a RAW release with no subtitles. So nuarr listens: Whisper on the GPU samples three windows across the track and identifies the language directly — ~0.2s of GPU per window, because language ID only needs the encoder, not a transcription. Windows the model isn't confident about are discarded before the vote, not counted against it; the survivors must agree. A manual override gets a deeper five-window listen before it's written.

And the write is a header edit — mkvpropedit flips the tag in milliseconds with zero bytes re-encoded. Across 480 files that fast path skipped 0.71 TB of pointless rewriting. Every fix restamps, notifies the arrs, and queues the rename.

THE SUBTITLE ENGINE

Pictures become text

Blu-ray subtitles are pictures (PGS). Plex has to burn them into the video on the CPU at playback — a forced transcode. Nuarr OCRs them to real text once, embeds the text track first, and demotes the bitmap. Signs & Songs on anime are burned in permanently on the GPU — 10-bit preserved end to end. And when the release already ships hand-made text subtitles, the redundant bitmap is simply dropped: no OCR spent re-reading what a human already typed. SDH tracks are recognised by role and never sacrificed.

NOTHING IS EVER AT RISK

Paranoid by design

The original is never deleted until its replacement is verified in place. If Sonarr upgrades a file while it's being encoded, Nuarr notices the bytes changed and discards its own output rather than clobber the better release. Locked by a viewer? The finished encode waits in a retry queue instead of being thrown away. A remux renumbers tracks, so every stored verdict is freshness-checked against the file before it's believed. Every destructive path can roll back.

TWELVE SPINDLES, ONE BRAIN

Disk-aware scheduling

The library spans twelve pooled disks, and nuarr watches every one natively — no vendor tools, no product-specific checks. It knows which spindle every file is on, spreads heavy jobs so no two share a disk, and names the destination as each commit lands. Each drive has its own colour, carried through every panel — and a new disk is picked up and assigned one automatically. When a viewer is streaming from a disk, work touching that spindle paces itself against their real buffer while everything else runs at full speed.

Amber = a viewer is on this spindle; work there follows the runway ramp. The rest don't slow down.
